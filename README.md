# COC 跑团 · AI 守密人

一个桌面版《克苏鲁的呼唤》第 7 版跑团工具。AI 同时担任**守密人（KP）**和你队伍里的**队友调查员**。

## 直接运行

双击 `COC跑团.exe` 即可。

这个 exe 是便携版：不需要安装，不需要 Node 环境，不依赖项目里的任何其他文件，复制到任意目录都能运行。首次双击会先在后台静默解压（约 10 秒，期间没有任何窗口），解压完成后立刻进入加载动画；之后每次双击约 0.2 秒就能看到动画。

## 界面结构

程序分两层界面。

### 主界面（开始界面）

启动后首先看到的是主界面，上面有这些按钮：

| 按钮 | 作用 |
|------|------|
| **开始** | 开启一段全新的调查（若已有进度会先确认是否覆盖） |
| **继续** | 接着上次的进度跑（**只有真正跑过至少一轮之后才会出现**） |
| 角色卡 | 管理玩家与 AI 的角色卡库 |
| 存档 | 查看 / 读取 / 删除 / 手动保存存档 |
| 模组管理 | 导入或粘贴模组，选用当前模组 |
| 规则书 | 打开规则书阅读器，带章节索引与搜索 |
| 设置 | 配置 AI 接口、叙事基调 |

底部显示当前使用的模型；没配模型或没配 Key 时用红字提示。

> 「继续」的判断标准是**玩家至少行动过一次**。只看到开场白、还没输入任何行动，不算跑过一次团，因此不会出现「继续」。

### 规则书阅读器

点 **规则书** 会打开一个独立窗口，左边是可搜索的章节索引，右边是 PDF 页面。

- 索引共 176 条，来自 PDF 书签，分三级（章 / 节 / 小节），点一下跳到对应页
- 搜索框支持按章节名过滤，命中的词会高亮
- 支持 `←` `→`、`PageUp` `PageDown` 翻页，页码框可以直接输入跳转
- 右上角「系统打开」可交给系统默认阅读器（应用内显示异常时的退路）

PDF 本体不入库（版权原因，见 `assets/README.md`）。缺文件时索引仍能正常浏览，
只有右侧页面会提示，并给出退路。索引数据在 `src/core/ruleBookIndex.js`。

### 跑团界面

点 **开始** 或 **继续** 后进入。左上角有 **‹ 主界面** 按钮，随时可以退回主界面（守密人正在叙述时会提示稍等）。

跑团界面里也保留了 **模组 / 存档 / 设置** 三个入口，不用退回主界面就能改配置。

## 第一次使用

1. 在主界面点 **设置**，填 AI 接口：

   | 项目 | 说明 |
   |------|------|
   | API 地址 | `https://api.deepseek.com/v1` |
   | API Key | 你的 DeepSeek 密钥（`sk-...`） |
   | 模型名 | `deepseek-chat` |

   点 **测试连接** 确认通了，再点 **保存**。

   也支持任意 OpenAI 兼容接口，比如本地 Ollama：地址填 `http://localhost:11434/v1`，Key 留空，模型填 `qwen2.5:14b`。

2. 回到主界面点 **开始**，进入跑团界面。

3. 左侧 **调查员 +** 建角色卡，点卡片可以改属性和技能。

4. **队友 +** 添加 AI 队友。**性格设定写得越具体，AI 演得越像真人**，比如：
   > 话少，抽烟，遇到血会下意识检查伤口。表面冷漠但护着队友。

5. 中间输入框写你的行动，回车发送。

## 模组

在主界面点 **模组管理**（跑团界面点右上角 **模组**，两者是同一个弹窗）：

- **从文件导入**：支持 `.txt` / `.md` / `.json`
- **手动粘贴**：把剧情大纲、线索、NPC 设定贴进去
- 不选模组也没关系，KP 会现场创作一个短篇调查故事

模组内容只有 AI 知道，它不会直接念给你听，而是拆成线索一点点透露。

## 核心机制

**所有骰子都在本地掷，AI 无法编造结果。**

AI 想让人检定时，只能输出一条指令：

```
[[CHECK: 侦查 | 角色=林默 | 难度=常规 | 原因=留意书架]]
```

本地规则引擎掷完骰、算出成功等级后，再把真实结果交回给 AI 让它描述后果。这样保证了：
- AI 不会"我掷出了 1，你大成功了"这种自说自话
- 成功率真的按你的技能值算
- SAN 损失真的会扣到角色卡上

支持的指令：

| 指令 | 作用 |
|------|------|
| `CHECK` | 技能检定（常规/困难/极难） |
| `SAN` | 理智检定，如 `1/1d6` |
| `DAMAGE` | 伤害，支持 `1d6+db` |
| `HP` / `MP` | 直接增减 |
| `ITEM` | 获得/失去物品 |
| `FLAG` / `CLUE` | 记录线索 |
| `SCENE` | 切换场景 |
| `END` | 模组结束 |

## 已实现的规则

- 骰子：d100、奖励骰/惩罚骰（单位骰掷一次，十位骰掷多次取最优/最劣）
- 成功等级：大成功(01) / 极难(≤1/5) / 困难(≤1/2) / 常规(≤技能) / 失败 / 大失败(≥96，技能<50 时仅 100)
- 角色卡：9 项属性、派生 HP/MP/SAN、伤害加值、体格、MOV、49 项技能
- 理智：SAN 检定、单次损失≥5 触发临时疯狂 + INT 检定、单次损失达当前 SAN 的 1/5 构成不定时疯狂、SAN≤20 濒临疯狂、SAN=0 永久疯狂
- 战斗：伤害掷骰含 db、重伤判定（单次伤害≥HP上限一半）、濒死

## 存档

每轮自动存档，也可以点 **存档** 手动保存多份。主界面的 **存档** 与跑团界面右上角的 **存档** 是同一个弹窗。

## 关于 AI 接口的说明

API Key 存在主进程的配置文件里（`%APPDATA%\coc-keeper\data\config.json`），不会进入网页层。所有请求由主进程发起，避免跨域问题。

队友可以用另一套模型省钱：设置里的「队友模型」填本地小模型，KP 用大模型。

## 打包与启动速度

`npm run dist` 会依次应用便携版启动器模板、打包、把产物移到根目录。

### 启动动画为什么之前出不来

便携版每次双击都要先把整个包解压一遍，**这段发生在 Electron 启动之前**。实测解压耗时约 10 秒，而这 10 秒里 Electron 还没被拉起，`src/splash.html` 的加载动画物理上不可能显示。

早期为此在 NSIS 启动器里嵌了一张静态图（`build/splash.bmp`），结果是「先看到一张静止的图，之后才看到动画」——图只是把空白填满，并不能动。

现在改成两条：

1. **去掉静态图**，不再有那张静止画面
2. **缓存解压结果**，让后续启动不再重复解压

缓存的做法是给 `portable.unpackDirName` 一个固定名字（`coc-keeper-ai-app`），启动器把它解压到 `%LOCALAPPDATA%\coc-keeper-ai-app`，并写入一个「版本 + 构建指纹」的戳文件（`.unpack-stamp`）。下次双击时戳一致就直接启动 Electron，跳过解压。

放 `%LOCALAPPDATA%` 而不是 `%TEMP%`：后者会被磁盘清理工具随手删掉，缓存白建。

实测效果：

| | 启动器阶段 | 双击到看见动画 |
|---|---|---|
| 首次（无缓存） | ~10.0 秒 | ~10.2 秒 |
| 之后每次 | ~50 毫秒 | **~200 毫秒** |

首次那 10 秒是静默等待（无窗口、无静态图），文件必须真的落盘一次。

### 指纹为什么不能只用版本号

缓存命中后启动器会直接跑缓存目录里的旧程序。如果只按 `version` 判断，改了代码但没升版本时，用户机器上会一直跑旧代码而且毫无察觉——这比启动慢严重得多。

所以戳里带一个构建指纹：`tools/patch-portable-nsi.mjs` 会对会打进 asar 的源码做内容哈希，任何实质改动都会让缓存失效。同时排除 `*.log` 这类运行时产物——否则程序每启动一次指纹就变一次，缓存永远命中不了。

### 这个模板是怎么生效的

electron-builder 的 portable 目标不接受自定义脚本（`NsisTarget.js` 里写死读模板，只有 installer 目标支持 `nsis.script`），所以 `tools/patch-portable-nsi.mjs` 在打包前把 `build/portable.nsi` 覆盖到 `app-builder-lib/templates/nsis/portable.nsi`，原模板备份为 `.orig`。

升级 electron-builder 后，要对照新版 `portable.nsi` 检查 `build/portable.nsi` 是否需要跟进。

### 验证工具

```powershell
npm run verify:stamp      # 指纹：稳定、对源码敏感、不受日志影响
npm run verify:startup    # 首次 vs 二次启动耗时
node tools/verify-portable-cache.mjs   # 端到端：缓存命中、戳失效重解压、运行中不删坏文件
```

改动打包配置后，建议再跑 `node tools/test-pdf-packed.mjs` 确认打包产物里的 PDF 提取没被打断。

包体积也做了裁剪，解压量从 470MB 降到 355MB：

- `electronLanguages` 只留 `zh-CN` / `en-US`，其余 53 个语言包（48MB）不打包
- 排除 `@napi-rs/canvas`（35MB 的 skia 图形库）。它是 `pdf-parse` 的可选依赖，只影响 PDF 渲染；我们只用文字提取，实测排除后提取结果完全一致
- 排除 `pdfjs-dist` 的 `web` / `types` / `image_decoders` 与所有 `.map`，文字提取不需要

### 排查启动问题时注意

本机若存在环境变量 `ELECTRON_RUN_AS_NODE=1`，Electron 会退化成纯 Node 进程，窗口完全不出现，且没有任何报错。排查「双击没反应」时先确认它没被设置。
